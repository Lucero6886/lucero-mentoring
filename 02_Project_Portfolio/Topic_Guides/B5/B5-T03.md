# B5-T03 — Đồng thiết kế thuật toán - phần cứng cho bộ giải mã Polar thích ứng

**Engineering & Research Mentoring Program (Lucero)** · ThS. Đinh Văn Nam (Mr. Lucero Dinh) — Khoa Điện–Điện tử, Trường Kỹ thuật, Đại học Phenikaa

> **File sinh tự động** từ `06_Data/research_packs.json` bằng `scripts/generate_research_packs.py`. Sửa tay sẽ bị ghi đè — muốn đổi nội dung thì sửa JSON rồi chạy lại script.

**English:** Algorithm-Hardware Co-Design of an Adaptive Polar Decoder

**Nhóm:** `B5` — Giải mã Polar thích ứng (Adaptive Polar Decoding)
**Loại:** `T` — Đồ án tốt nghiệp · **Sàn năng lực:** L4 · **Mã ngắn khóa hiện tại:** `B11`

> **Vai trò trong chương trình.** Complete product + quantitative evaluation. Có thể trở thành paper candidate nếu phần extension tạo insight mới và comparison đủ mạnh.

**Câu hỏi nghiên cứu:** Làm thế nào ánh xạ adaptive Polar decoding thành kiến trúc phần cứng để lợi thế average-case của thuật toán vẫn tồn tại sau fixed-point, control, memory và interface overhead?

## Sản phẩm phải làm ra

Algorithm baseline; operation/memory model; fixed-point; RTL critical blocks; reliability-cost Pareto

Đây là phần **riêng của đề tài này**. Nếu cuối kỳ không có đủ những thứ trên thì đề tài chưa xong,
dù đã bỏ bao nhiêu thời gian.

## Trước khi bắt đầu — phải đọc

- T05–T10 foundations
- algorithm–hardware co-design
- fixed-point
- resource sharing
- FSM/control
- memory architecture
- FPGA timing/power

Tài liệu cụ thể theo hướng: [`09_References/READING-LIST.md`](../../../09_References/READING-LIST.md)

## Phải hiểu được (không nhìn tài liệu)

- algorithmic operation vs hardware cycle
- resource sharing vs parallelism
- buffer/memory bottlenecks
- average/worst latency
- energy/frame
- control overhead

## Phải dựng / code / chế tạo

- fixed-point adaptive model
- module partition
- SC datapath
- reliability unit
- controller
- enhanced-processing interface
- RTL TB + FPGA build

## Thí nghiệm và đo kiểm mặc định

- bit-exact verification
- resource-sharing alternatives
- fmax/latency/throughput
- activation-dependent average latency
- power/energy estimate
- ASIC-feasibility synthesis if available

## Câu hỏi mentor sẽ hỏi đi hỏi lại

1. Algorithm saving nào biến mất khi đưa lên hardware?
2. Control/memory overhead là bao nhiêu?
3. Average-case metric đo trên distribution nào?
4. Kiến trúc có scale với N không?

## Khi nào mới nói tới bài báo

FPGA implementation validated; algorithmic gain survives hardware overhead; có architecture comparison và average/worst-case metrics; paper-ready khi co-design tạo insight rõ.

> Một PCB project không trở thành nghiên cứu chỉ vì thêm chữ “nghiên cứu” vào tên. Muốn lên R phải có biến, baseline, metric, hypothesis và experiment có kiểm soát.
